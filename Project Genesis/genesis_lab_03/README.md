# PROJECT GENESIS — Experiment 03

## 질문

기존 입력 좌표 `x, y`를 사용하는 AI가 지도 관측만으로 더 설명력 높은 새 표현 `z = f(x, y)`를 만들 수 있는가?

이 실험은 **자율적 과학 발견이나 AGI의 입증이 아니라**, 이미 알려진 *기호적 특징 생성 / 프로그램 열거(symbolic feature synthesis)*를 이용한 검증용 프로토타입입니다.

## 시작 방법

1. `genesis_lab_03.html`을 Safari나 Chrome으로 엽니다. 네트워크/설치/API/서버가 필요 없습니다.
2. 기본값 `XOR`에서 **+40 관측**을 누릅니다. 모델이 `x × y`를 유용한 표현으로 선택하는지 확인합니다.
3. `원형 영역`으로 바꾸고 **+120 관측**을 누릅니다. `x × x + y × y`를 찾는지 관찰합니다.
4. `물결 경계`로 변경해 실패 사례를 확인합니다.
5. `왼쪽 절반만` 관측하도록 바꾸면 비관측 영역으로의 외삽 위험을 확인할 수 있습니다.
6. CSV 버튼으로 각 실험의 관측 샘플과 요약을 내려받을 수 있습니다.

## 모델 비교

- **선형 모델**: 입력 `x, y`에 대해 로지스틱 회귀(경사하강 학습). 모든 관측 데이터에서 학습하되, 검증 분할의 샘플은 사용하지 않습니다.
- **기억 모델**: 동일한 훈련 데이터에서 가까운 5개 사례의 거리를 가중해 예측하는 k-NN.
- **좌표 생성 모델**: 원래 좌표 `x, y`에 `+, −, ×`를 적용한 표현식들을 *문법으로 열거하여* 만들고, 복잡도 최대 7의 후보 134개에서, 훈련 데이터로 임계값을 맞춘 뒤 검증 오류와 식의 복잡도를 기준으로 선택합니다. 표면상 `z=f(x,y)`라는 새로운 특징을 만들지만 실제로는 이 특징 하나에 대한 임계값 분류기입니다.

모든 모델은 관측 시 제공된 **정답 레이블**을 사용합니다. '자기지도학습'이나 '비지도 학습'이라고 해석하면 안 됩니다.

별도로 생성한 **900개의 평가용 좌표**는 모델 훈련이나 모델 선택에 쓰지 않습니다. 다만 사용자가 시험 정확도를 보고 시드를 바꾸는 행위 자체는 인간의 개입이므로, 논문용 성능 주장에는 미사용 최종 시험 세트를 추가로 확보해야 합니다.

## 재현 가능한 검증 결과

실험 스크립트: `node benchmark_genesis03.js` (Node.js 필요, 별도 npm 패키지 없음).

훈련 관측 160개, 20개 시드(1000~1019), 각 시드별 새 평가 표본 900개. 수치는 정확도 평균 ± 표준편차(퍼센트포인트).

| 환경 | 선형 모델 | 기억 모델 | 새 좌표 모델 |
|---|---:|---:|---:|
| XOR | 53.0 ± 6.3% | 94.6 ± 1.1% | 99.6 ± 0.4% |
| 원형 경계 | 63.2 ± 5.6% | 94.8 ± 1.1% | 99.6 ± 0.4% |
| 포물선 | 88.9 ± 0.9% | 96.0 ± 1.3% | 97.2 ± 2.3% |
| 대각선 대조군 | 96.9 ± 1.3% | 96.5 ± 0.9% | 99.6 ± 0.4% |
| 주기적 줄무늬(한계 사례) | 50.3 ± 1.9% | 72.9 ± 3.5% | 61.9 ± 4.2% |

이 실험에서는 모델별 표현력과 연산량이 다르므로, 결과를 '동일한 모델 용량에서의 효율성'으로 해석해서는 안 됩니다. 또한 인위적으로 선택한 작은 분류 과제들의 결과일 뿐 일반지능의 증거가 아닙니다.
