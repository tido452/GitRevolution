# PROJECT GENESIS — Experiment 05

## 핵심 질문

**환경에서 발견한 수학적 표현을 새로운 계산 도구(합성 연산, learned macro)로 등록하면, 처음 보는 관련 문제를 더 빠르고 정확하게 해결할 수 있는가?**

실험 가능한 실제 알고리즘이다. 단, **신경망·LLM이 아니며, 기호 회귀·유전적 프로그래밍과 합성 연산 라이브러리 학습의 축소형**이다. 이를 천재적 직관이나 범용 AI의 증거로 과장하지 않는다.

## 빠른 실행

`genesis_lab_05.html` 파일을 Chrome/Safari에서 연다. 외부 API, 네트워크, 설치가 필요하지 않다.

1. 기본 `원형 영역`에서 **① 규칙 발견** 클릭: 120개 정답 라벨 관측 중 75%로 진화, 25%로 선택, 48세대, 개체 100개.
2. **② 연산 등록** 클릭: 발견한 원본 표현식 `f(x,y)`를 `M1(x,y) = f(x,y)`로 보관.
3. 기본 `더 작은 원`에서 **③ 비교 실험** 클릭: 같은 새 문제 관측을 이용하여 네 가지 방법을 비교.
4. 소스와 타깃을 XOR, 줄무늬 등으로 바꿔 도움이 안 되는 경우도 관찰.
5. CSV를 저장하거나 새 난수 시드로 다시 실험.

## 내부 구현 (중요)

### 1. 표현 구조

수식은 노드 트리(AST). 원시 연산 집합: `x, y`, 소수 상수, `+`, `−`, `×`, `sin`, `cos`, `square`, `absolute`, `negation`.

예를 들어 `(x*x) + (y*y)`는 `add(mul(x,x), mul(y,y))` 구조다. 사람이 허용한 연산의 집합 안에서만 탐색한다.

### 2. 학습 / 탐색

(1) 무작위 수식 후보 집단 구성 → (2) 각 수식으로 예측하고 정답 라벨과 비교 → (3) 학습 정확도 및 수식 복잡도에 따라 선택 → (4) 서브트리 교차·변이 → (5) 반복. 

기본 목표 점수 `training_accuracy - 0.0025 * max(0,tree_nodes-2)`; 최종 표현 선택은 훈련에 쓰지 않은 검증 라벨에서 이루어짐. 각 수식의 예측 임계값과 부호 방향은 훈련 데이터에서만 최적화된다.

### 3. 새로운 합성 연산 (GENESIS 05)

학습한 식을 새 함수 노드 `M1(x,y)`로 저장한다. 검색/평가할 때 `M1`은 일종의 단일 노드지만, 실행은 저장된 원래 수식을 그대로 평가한다. 따라서 새로운 원시 수학 연산이 아니라 **학습된 수식의 이름 있는 재사용 가능한 매크로**다. 매크로 정의의 저장·추론 비용이 실제로는 따로 발생한다.

새 문제에는 관련 매크로를 초기 후보에 넣고 교차/변이 과정에서 다른 수식과 조합할 수 있게 한다. 후속 문제에 도움될 것이라는 보장은 없다.

### 4. 통제군

- **5-NN**: 이웃 사례 암기와 검색(라벨 전체 사용).
- **Cold start**: 해당 문제에서 새로 GP 탐색.
- **Raw reuse (GENESIS 04 방식)**: 원본 표현식을 트리 형태로 가져와 초기 집단에 넣는다. 이는 매크로가 아니라 단순히 이전 해답을 재사용하는 효과를 평가한다.
- **Macro reuse (GENESIS 05)**: 학습된 수식을 하나의 복합 연산 노드로 추가한 뒤 탐색한다.

Cold, Raw reuse, Macro reuse는 **새 타깃의 샘플, 탐색 집단 크기, 세대 수, 난수 시드를 공유**한다. 초기 개체가 다르므로 후속 무작위 경로 자체가 정확히 일치하는 것은 아니다. 5-NN은 같은 관측 라벨을 모두 학습할 수 있고, GP는 데이터의 75%로 학습하고 25%로 검증한다.

- **중요한 공정성 문제:** Raw reuse와 Macro reuse는 이전 세계를 학습하는 데 추가 데이터와 연산을 이미 사용했다. 따라서 새 문제에서의 탐색 예산이 같아도 **총 학습 자원**은 Cold start보다 많다. GP 매크로의 비용은 단일 노드로 계산하는 반면 내부 정의를 실제 실행해야 한다. 정확도는 작업별 성능을 말할 뿐 총 계산 효율을 입증하지 않는다.

### 5. 평가

훈련/검증 점은 모델이 학습·선택에 사용한다. 1,000개 독립 시험점의 실제 정답을 평가에만 사용한다. 브라우저 화면의 시험 결과를 보면서 실험 설정을 반복 변경할 경우 연구자 수준에서 시험 데이터에 과적합할 위험이 있으므로 최종 논문 수준의 평가에는 아직 보지 않은 새 과제/시드가 필요하다.

## Node.js 재현

```bash
node benchmark_genesis05.js 12
```

이 스크립트는 4개 과제쌍에 대해 12개의 난수 시드를 사용한다. 원본 문제는 140개 관측, 진화 45세대, 100개체를 사용하고 새 문제는 70개 관측, 12세대, 100개체를 사용한다. 원본 학습 자원과 매크로 구조 비용은 새 문제의 세대 수에 포함하지 않는다. 2026-10-28 실행한 탐색적 결과(시험점 1,000개, 12개 시드 평균)는 다음과 같다.

| 원본 → 새 문제 | Cold | 원본 식 재사용 | M1 재사용 |
|:--|--:|--:|--:|
| XOR → XOR threshold | 97.1% | 98.3% | 97.9% |
| Circle → Small circle | 92.8% | 96.5% | 97.8% |
| Stripes → Threshold-shifted stripes | 81.0% | 91.9% | 89.7% |
| XOR → Stripes (관련 낮음) | 81.0% | 81.6% | 82.5% |

위 수치는 선택된 과제와 설정에서의 결과이지 일반적인 우월성의 확증이 아니다. 특히 주기적인 문제에서는 합성 연산이 원래 수식 재사용보다 나빴다.
